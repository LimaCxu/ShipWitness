# Contributing

1. Open an issue describing the user-visible outcome and acceptance criteria.
2. Keep each pull request focused on one product change.
3. Run `npm run check` before submitting.
4. Include browser acceptance evidence for UI changes.
5. Never commit secrets, customer data, or generated `data/*.json` stores.

ShipWitness uses conservative verdicts: missing business-path evidence must remain `evidence_insufficient`, never inferred as passed.
