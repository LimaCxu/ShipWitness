# 受控试点反馈闭环

顶部的 **反馈** 入口用于记录真实试点中的问题、功能建议和使用体验。反馈属于当前工作区，可关联一个仍在使用的项目，也可以作为工作区通用意见提交。

所有成员都能提交并查看反馈。管理员和审批人可以把反馈从“待分级”推进到“已分级”“已排期”“已解决”或“不处理”；普通成员不能更改处理状态。新反馈会进入管理员和审批人的团队待办，阻断使用的反馈按高优先级展示。

项目反馈可以由管理员或审批人选择 **转为标准**。系统会生成一条带来源关联的停用验收标准草稿，并把反馈推进到“已排期”。标准草稿不会直接影响发布结论；负责人必须在标准库中补充浏览器步骤、检查正确结果并主动启用。每条反馈只能转化一次，工作区通用反馈必须先明确关联项目。

处理反馈使用结构化弹窗记录状态和说明。“已解决”与“不处理”必须填写最终结论，防止只改状态却没有留下判断依据。

当来源标准被启用并进入新验收任务时，反馈来源会固化在该任务的标准快照中。只有这条来源标准获得真实 `passed` 结果，系统才会自动把仍处于“已排期”的反馈标记为“已解决”。验证记录保存任务编号、标准版本、结果编号、执行器和时间；反馈中心可直接打开对应任务查看证据。失败、证据不足或其他无关标准通过都不会自动关闭反馈。

如果问题再次出现，管理员或审批人必须使用 **重新打开** 并填写回归原因。系统会把当前验证移入历史记录，再将有关联标准的反馈恢复为“已排期”（没有标准的恢复为“已分级”）。已结束反馈不能通过普通状态修改绕过这个流程。后续复验通过会产生新的当前验证，旧验证和重开原因继续保留。

反馈创建、状态变化和导出都会进入哈希链审计。管理员与审批人可以导出 `shipwitness.pilot-feedback.v1` JSON 快照，作为试点周报、版本复盘或客户交付记录的附件。导出不包含密码、会话令牌或部署密钥。

反馈中心用于产品改进，不替代验收标准和发布门禁。影响当前发布正确性的反馈仍应转成可执行验收标准或证据关联的返工单，再由验收结果决定能否发布。
