# 上线就绪中心

上线就绪中心供工作区管理员判断当前 ShipWitness 实例适合哪一种运行环境。它读取服务可验证的运行状态和运维方明确登记的证据元数据，但不会返回密码、主密钥、SMTP 凭据或安全报告正文。

## 结论分级

- **仅限本地或开发环境**：至少一个阻断项未通过，不应对外开放。
- **可进入受控试点**：没有阻断项，但仍有需要人工处理或确认的警告；应限制用户、数据和访问范围。
- **具备公网候选条件**：当前检查没有阻断或警告，可进入正式发布审批；这不等于安全认证，也不能替代独立评审。

## 检查口径

| 检查 | 级别 | 通过条件 |
| --- | --- | --- |
| 生产数据库 | 阻断 | 健康检查确认使用 PostgreSQL |
| HTTPS 公网地址 | 阻断 | `SHIPWITNESS_PUBLIC_URL` 是无凭据的 HTTPS 地址 |
| 主密钥 | 阻断 | `SHIPWITNESS_MASTER_KEY` 是规范的 32 字节 Base64 密钥 |
| 高权限账号两步验证 | 警告 | 当前工作区所有管理员和审批人均已启用 TOTP 两步验证 |
| 审计链完整性 | 阻断 | 当前工作区审计哈希链验证通过 |
| 最近验证备份 | 警告 | `SHIPWITNESS_LAST_VERIFIED_BACKUP_AT` 记录在过去 24 小时内，且该时间只应在备份校验成功后写入 |
| 独立安全评审 | 警告 | `SHIPWITNESS_SECURITY_REVIEW_REFERENCE` 指向真实评审工单或报告编号 |
| 安全发现整改 | 严重/高危阻断，中低危或临时接受警告 | 严重和高危发现必须通过复测；管理员接受风险最长 90 天且不能伪装成通过 |
| 签名安全整改证据包 | 警告 | 结构化评审的最新发现状态必须生成并验证 Ed25519 签名证据包 |
| 版本支持周期 | 开发版警告 / 稳定版阻断 | 开发版只允许受控试点；稳定版必须处于已公布的支持周期内 |
| 邮件通知 | 警告 | SMTP 已启用且没有最终失败邮件 |
| GitHub 自动同步 | 警告 | 使用 GitHub 项目时已配置签名 Webhook；未使用 GitHub 时不要求 |
| 运行健康 | 警告 | 没有超时任务或最终失败 Webhook |
| 目标白名单 | 通过项 | 非本机目标默认拒绝，并显示显式允许的来源数量 |

## 使用方式

管理员进入账户与工作区管理面板即可查看结论和逐项整改建议。选择“导出报告”会下载 `shipwitness.readiness.v1` 当前快照的 JSON 表达；报告适合附在试点或发布审批记录中，但环境变化后应重新生成。

备份时间、评审编号和评审日期属于运维方声明的证据元数据，不是 ShipWitness 自动完成了备份或安全评审的证明。外部评审超过一年后会重新变为警告。部署负责人必须保留对应的校验输出、恢复演练记录和独立报告，并对真实性负责。

`GET /api/support` 公开返回机器可读的支持政策与当前版本状态，不包含工作区数据。开发版固定为 `evaluation_only`；稳定版缺少发布日期、停止支持日期或已经到期时，上线就绪中心会阻断公网候选结论。
